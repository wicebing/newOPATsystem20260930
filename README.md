# OPAT 執行與績效分析

可在 GitHub Pages 運作的純前端報表。選取多份原始 `.xlsx` / `.xls` 後，瀏覽器直接合併資料並呈現總覽、執行分析、開立分析、績效點數、個案追蹤與資料檢核。原始資料不會上傳伺服器，也不會預先放入儲存庫。

## 使用

```bash
npm install
npm run dev
```

同時上傳 `1150908_OPAT個案資料g.xlsx` 與 `1150908_OPAT個案資料h.xlsx`。g 檔使用原有的竹北、竹東院區；h 檔若院區空白，會依檔名、帳號或病歷號判定為新竹。其他無法判定的資料會在「資料檢核」提示。

## 計算規則

- 每筆 `執行次數明細` 各自按當地時間 `08:00` 切分績效月。例如 `2026-08-01 07:59` 屬 7 月，`08:00` 屬 8 月。
- 護理只計注射抗生素的有效執行時間。口服、Saline 和其他稀釋液不計。負退量但有施打時間的紀錄保留，並列入檢核。
- Saline、Taita No.4 等稀釋液、口服藥、非 OPAT 抗生素與針具先排除藥品執行與重複醫令檢核，不進入開立偏好、護理與藥劑績效、施打趨勢或完成率，也不能在藥品分類中勾選回來。醫師偏好的分母只採有納入注射抗生素的 OPAT 療程；未知注射品項維持待確認，不自動當作抗生素。管理費是獨立的帳號層級申報資料，即使申報欄位記在稀釋液原始列，仍依申報規則保留。
- 原始列先依同院區、病歷號，以及 `帳號`、`執行人員明細`、`診療行為`、`健保碼`、`藥品八碼`、`組合商品名`、`確認日期`、`開始日`、`結束日`、`總數量`、`天數`、`頻率` 比對醫令。只有其餘欄位完全相同（允許轉急診、轉住院、失敗註記不同），或同一單日排程的 QD/Q24H/ONCE/STAT 單次醫令僅執行時間不同，才判為重複列。時間押錯日期時優先保留與預定日最接近的紀錄；Q12H 或跨日時間不同者暫保留待核對。轉診與失敗註記仍保留用於療程狀態。
- 同一療程、藥品、完全相同的執行時間只計一次，警示列出對照檔案與列號。單日、單次醫令以開始日與結束日相同的預定日作為施打歸屬日；其餘依執行明細日期。QD 同一歸屬日最多一次、Q12H 同一歸屬日最多兩次。歸屬日與執行明細日期不一致時保留施打並提示核對，績效月份仍依原始執行時間的 08:00 邊界計算。
- 護理績效表同時列出原始施打明細、排除重複或超頻次數、有效施打，便於與人工表對帳。
- 藥劑按 `執行次數 > 0` 且該月有執行時間的注射抗生素藥品列計數；確認重複的原始列不重複計點，但僅因護理時間去重或超頻而排除的列仍按藥品保管規則處理。同一列跨月時，在各有執行的月份各計一筆。
- 醫事只採 `39029C管理費數量 > 0` 的非 `門診轉OPAT「D1」` 紀錄，同院區同帳號僅保留最早一筆申報。有執行時間時按 08:00 歸月；只有日期時按確認日期的曆月歸屬，不把月初午夜誤移到上月。報表顯示「申報數」，不將申報直接視為完成療程的證明。
- 同院區同病歷號、開案日相距 7 日內的門診 D1 與 D2-D7 合併為一個療程。其他來源依帳號識別療程。
- 點數：護理每次 `0.1`、藥劑每筆 `0.05`、醫事每筆申報 `0.025`。

新藥品不會自動視為注射抗生素；到「資料檢核」確認並勾選後，相關護理與藥劑結果會即時重新計算。
「資料檢核」的重複醫令表及匯出 Excel 的「重複醫令核對」工作表保留原始檔名、列號、對照列及兩邊的執行時間；「Step1清理資料」已排除確認重複的列。選定績效月份時，Step1 僅保留執行時間落在該月 `08:00` 至下月 `08:00` 的列；跨月同列的執行次數、時間與人員明細只保留本月部分，確認日期與開始／結束日不作執行月份判定。選「全部期間」時則保留完整原始明細。僅帳號與執行人員相同不足以認定重複，避免誤刪正常的多日施打。

檔名中的下載日期（例如 `1150908`）視為資料快照日。完成率與未執行只評估快照日前已到期的排程，快照日與其後為待執行；若多檔日期不同，保守採最早日期並提示。沒有可辨識日期時暫用系統日期並提示。每日預定與實際施打圖使用單柱顯示預定內完成、未完成與「未對應排程」，並提供各院區獨立圖。已到期的單日醫令按預定日對齊；提前施打但預定日尚未到期者仍顯示於原始執行日。「未對應排程」不代表臨床上一定多打。

每週開立圖以週一至週日分組。「新療程」依合併 D1/D2 後的最早確認／看診日計一次；「開立施打次數」按注射抗生素醫令的預定施打日及 QD、Q12H 等頻率推算，包含尚未到期的排程，不等於實際施打。重疊醫令以同療程、藥品、日期的最高預定次數計，稀釋液不納入。選擇月份時只統計該月內的開案日或預定施打日，即使週一落在前月。週圖、各院區數字與 Excel「每週開立量」工作表皆依相同規則產生。預設月份依資料快照日的 08:00 績效切月選取。

每週圖、醫令頻率、非 QD 醫令明細與醫師用藥偏好集中在「開立分析」。醫令頻率以去重後的注射抗生素醫令筆數計，不以施打次數計；選擇月份時，納入起訖日與該月重疊的醫令。非 QD 明細列出醫師、藥品、頻率、帳號與原始檔列號，包含頻率未填的醫令以便檢核，並排除稀釋液、口服藥及確認重複的資料。

「療程來源」與「常用注射抗生素」的 BAR 直接標示數量與占本範圍療程／施打總量的比例。「施打時段」按整點堆疊三院區執行量，並以相同縱軸刻度分院區比較。醫師開立偏好熱圖按療程開案月份統計：某藥比例 = 該醫師開立此藥的不同 OPAT 療程數 / 該醫師全部 OPAT 療程數；不按施打次數計，同一療程多藥可分別計入。時段及完整醫師／藥品矩陣也可匯出至 Excel。

「有執行」表示至少有一筆注射抗生素施打，不代表療程已完成；「未執行」為預計結束日已過但沒有施打紀錄。失敗個案與轉急診/住院依原始欄位另列。療程來源分門診、住院、急診。

## GitHub Pages

此資料夾可作為單獨的 GitHub repository。推送到 `main`，在 repository 的 **Settings → Pages** 將來源設為 **GitHub Actions**。工作流程會執行測試與建置後部署 `dist`。Vite 使用相對 `base`，可放在 GitHub Pages 的 repository 子路徑。請勿把院內個案 Excel、CSV 或其他可識別病人的資料提交到公開儲存庫。

```bash
npm run test
npm run build
```
